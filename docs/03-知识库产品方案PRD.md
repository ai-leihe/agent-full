## 1. 产品目标与成功度量

### 1.1 产品目标（三个层次）

| 层次 | 目标 | 衡量方式 |
|---|---|---|
| **能力目标** | 补齐企业级知识库的地基能力（混合检索 / 重排 / 权限 / 持久化 / 问答） | 功能验收清单全绿 |
| **效果目标** | 问答准确率、召回质量达到行业可用水平 | RAGAS 四指标达标 |
| **业务目标** | 真实降低人工支持成本 | 分流率 ≥ 40% |

### 1.2 北极星指标

> **北极星指标：有效问答数**（用户提问后未转人工且未点踩的会话数）
>
> 理由：它同时反映了"用户在用"（量）和"用得满意"（质），且与业务价值（降低人工成本）直接挂钩。

### 1.3 关键指标目标（MVP 上线后 3 个月）

| 类别 | 指标 | 目标 |
|---|---|---|
| 效果 | 问答准确率（人工抽检） | ≥ 90% |
| 效果 | RAGAS Faithfulness | ≥ 0.90 |
| 效果 | RAGAS Context Recall | ≥ 0.85 |
| 效果 | RAGAS Context Precision | ≥ 0.80 |
| 体验 | 检索 P95 延迟 | < 500ms |
| 体验 | 问答首字 P95 | < 2s |
| 业务 | 分流率 | ≥ 40% |
| 业务 | 用户好评率 | ≥ 85% |
| 内容 | 90 天内更新文档占比 | ≥ 70% |

## 2. 需求清单与优先级

### 2.1 优先级方法说明

采用 **MoSCoW + RICE 双轨**：

- **MoSCoW**：先划分"必做/应做/可做/不做"，其中 **Must 工作量占比控制在 60% 左右**
- **RICE**：在 Should/Could 内部排序，`RICE = (Reach × Impact × Confidence) / Effort`

### 2.2 MVP（v1.0）需求清单 —— Must Have

> **MVP 判定标准**：没有它，产品无法交付给真实企业客户。

#### M-01 知识采集（基础）

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 本地文件上传 | 支持 PDF/Word/Excel/PPT/TXT/MD/HTML | 高 | 各格式可上传并成功解析出文本 |
| 批量上传 | 支持多选/拖拽目录，保留相对路径 | 高 | 100 个文件批量上传成功，失败项可重试 |
| 文档列表管理 | 列表/搜索/筛选/删除/重新索引 | 高 | 支持按状态、类型、时间筛选 |

#### M-02 知识加工（基础）

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 解析器（现有 3 种 + Excel/PPT） | txt/md/pdf/docx + xlsx/pptx | 高 | 解析准确率 > 95%（文本层完整文档） |
| 清洗器（现有 3 种） | basic / markdown / sensitive | 中 | 复用现有 |
| 切片策略（现有 3 种 + document_aware） | recursive / fixed / markdown / document_aware | 高 | 切片参数可配，按文档类型选策略 |
| 切片预览 | 展示所有 chunk 及边界 | **高（差异化）** | 可查看、可分页、可搜索 |
| 切片编辑 + 锁定 | 人工合并/拆分/改写，锁定后重索引不覆盖 | **高（差异化）** | 编辑后重新索引，锁定 chunk 内容不变 |

#### M-03 知识存储（基础）

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 持久化向量库 | pgvector 实现 | **极高** | 重启服务后索引不丢失 |
| 向量库 Skill 化 | 实现 `SearchableIndex` 协议 | 高 | 可通过配置切换后端 |
| 元数据库 | 文档/chunk/权限元数据持久化 | 极高 | 结构化存储，支持查询 |
| Embedding 绑定校验 | 索引记录模型三元组，不匹配拒绝检索 | 高 | 换模型后旧索引报明确错误 |

#### M-04 知识检索（核心）★

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| **向量召回** | dense retriever | 极高 | 复用现有，接入持久化库 |
| **关键词召回（BM25）** | sparse retriever | **极高** | 精确匹配查询命中率显著提升 |
| **RRF 融合** | 融合多路召回结果 | **极高** | 融合后 Recall@5 相比单路提升 ≥ 10% |
| **Rerank 重排** | BGE-reranker-v2-m3 | **极高** | 引入后答案准确率提升 ≥ 10pp |
| **检索参数可配** | 全链路参数暴露 + 档案保存 | **高（差异化）** | 参数改动实时生效，可保存为档案 |
| **检索测试台** | 链路追踪可视化 | **高（差异化）** | 展示每跳耗时与结果 |
| 查询改写 | 多轮指代消解 + 短查询扩展 | 高 | 多轮对话中"它的参数"能正确解析 |

#### M-05 权限管理（准入条件）★

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 用户与认证 | 本地账号 + Session/JWT | **极高** | 可登录、可登出 |
| 角色体系 | 预设 6 种角色 | 极高 | 权限矩阵生效 |
| 知识库级权限 | 成员/角色授权 | 极高 | 无权用户看不到知识库 |
| **文档级 ACL** | 文档粒度授权 | **极高** | 无权限文档**不出现在检索结果中** |
| **权限前置过滤** | 过滤条件注入召回阶段 | **极高** | 无权限内容不进入 LLM 上下文 |
| 多租户隔离 | tenant_id 强隔离 | 高 | 跨租户数据完全不可见 |
| 审计日志 | 关键操作记录 | 高 | 可查询、可导出 |

#### M-06 知识更新（基础）

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 文档删除 | 软删 + 硬删（索引同步清除） | 高 | 删除后检索不到 |
| 文档重新索引 | 手动触发单个/批量 | 高 | 重新索引成功且不影响其他文档 |
| 指纹比对增量更新 | 内容未变则跳过 | 中 | 重复导入同一文档零成本 |

#### M-07 知识运营（基础）

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| 检索日志 | 记录 query / 结果 / 耗时 | 高 | 可查询、可追溯 |
| 问答日志 | 记录会话 / 答案 / 引用 | 高 | 可查询 |
| 基础指标看板 | 文档数 / 问答量 / 好评率 / 延迟 | 高 | 可视化展示 |
| 未答问题池 | 收集拒答与点踩问题 | **高（差异化）** | 按频次排序，可认领 |

#### M-08 智能应用（核心）★

| 需求 | 说明 | RICE | 验收标准 |
|---|---|---|---|
| **知识问答页** | 多轮对话 + 流式输出 | **极高** | 流畅问答，支持多轮上下文 |
| **引用溯源** | 答案标注 [n] 并可点击查看原文 | **极高** | 每个 [n] 可展开看原文片段 + 文档位置 |
| **拒答机制** | 无依据时明确拒答并推荐追问 | **极高** | 无关问题不编造，拒答率合理 |
| 用户反馈 | 点赞/点踩 + 原因 | 高 | 反馈可入库、可统计 |
| **开放 API** | 问答 + 检索接口 | 高 | 可被外部系统调用 |

### 3.2 v1.0 MVP —— 「能用且敢用」

**目标**：交付给首批试点客户，跑通"知识入库 → 问答 → 反馈"闭环。

| 阶段 | 内容 | 交付物 |
|---|---|---|
| **P0 地基** | 元数据库 + pgvector + 权限模型（表结构 + 中间件） | 可持久化的知识库底座 |
| **P1 摄取链路** | connector/parser/enhancer/splitter 槽位与实现；切片预览与编辑 | 完整的索引流水线 |
| **P2 检索链路** | dense + sparse 召回 + RRF + Rerank + 参数化 | 混合检索能力 |
| **P3 问答链路** | rewriter + guard + assembler + generator + postprocess | 端到端问答 |
| **P4 前端** | 管理控制台（知识库/文档/切片/权限/日志）+ 问答端 | 产品门面 |
| **P5 差异化** | 检索测试台 + 编排工作台扩展（查询链路） | 白盒能力 |
| **P6 验收** | 在真实语料上跑通；RAGAS 基线测评 | MVP 交付 |

**MVP 交付判定（DoD）**：

- [ ] 能上传 1000+ 文档并建立索引，重启不丢
- [ ] 混合检索 + Rerank 生效，Recall@5 ≥ 0.85
- [ ] 文档级权限生效，无权限内容零泄露
- [ ] 问答端到端可用，引用可点开溯源
- [ ] 检索测试台可展示完整链路
- [ ] 关键指标看板可用

## 4. 关键功能的验收标准（详细）

### 4.1 混合检索 + RRF【M-04】

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 关键词精确匹配 | 含型号/错误码的查询命中率 ≥ 95% | 构造 50 条精确匹配测试查询 |
| 语义泛化 | 同义改写查询命中率 ≥ 85% | 构造 50 条改写测试查询 |
| RRF 融合增益 | Recall@5 相比单路最优提升 ≥ 10% | 在评测集上对比 |
| 参数生效 | 修改参数后下次检索立即生效 | 手动验证 |

### 4.2 Rerank【M-04】

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 准确率提升 | 引入后答案准确率提升 ≥ 10pp | 评测集 A/B |
| 精度提升 | Context Precision 提升 ≥ 0.10 | RAGAS 对比 |
| 延迟可控 | 重排环节 P95 < 300ms | 压测 |
| 降级 | Rerank 服务不可用时自动直通，不报错 | 故障注入 |

### 4.3 权限前置过滤【M-05】

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 零泄露 | 无权限文档在检索结果中**零出现** | 构造 100 条跨权限查询全量验证 |
| 无痕迹 | 不提示"存在但无权访问" | 人工检查返回内容 |
| 性能 | 带权限过滤的检索延迟增幅 < 20% | 压测对比 |
| 租户隔离 | 跨租户查询返回空，且无法通过参数绕过 | 渗透测试（尝试前端传 tenant_id） |
| 缓存隔离 | 跨租户缓存不串数据 | 构造相同 query 跨租户测试 |

### 4.4 引用溯源【M-08】

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 标注完整 | 答案中每个事实性陈述有引用标注 | 人工抽检 50 条 |
| 可跳转 | 点击 [n] 可展开原文片段与文档位置 | 交互测试 |
| 引用准确 | 引用内容确实支持该陈述（无错配） | 人工抽检，准确率 ≥ 95% |

### 4.5 拒答机制【M-08】

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 不编造 | 知识库无相关内容时拒答率 ≥ 95% | 构造 50 条域外问题 |
| 不误拒 | 知识库有答案时拒答率 ≤ 5% | 构造 50 条域内问题 |
| 有帮助 | 拒答时提供追问建议或转人工入口 | 交互检查 |

| | 拒答率 | 拒答会话占比 | 监控 | 效果分析 |
| **L3 体验** | 检索 P95 | 召回+融合+重排 | < 500ms | 性能 |
| | 首字 P95 | 提问到首字 | < 2s | 性能 |
| | 完整响应 P95 | 提问到答案完成 | < 5s | 性能 |
| **L3 内容** | 新鲜度 | 90 天内更新文档占比 | ≥ 70% | 内容健康 |
| | 零命中文档占比 | 长期无命中 | 监控 | 内容健康 |
| | 切片异常率 | 过短/过长/噪声切片占比 | ≤ 5% | 内容健康 |
| **L4 成本** | 单次问答成本 | 总成本/问答数 | 监控 | 成本 |
| | 缓存命中率 | 语义缓存命中 | ≥ 20% | 成本 |
| | Token 消耗 | 输入/输出 | 监控 | 成本 |

### 5.2 运营闭环机制

| 触发条件 | 动作 |
|---|---|
| 未答问题 Top10 出现同主题 ≥ 3 次 | 自动创建"知识补充任务"并指派 |
| 好评率单周下降 > 10pp | 告警 + 触发全量评测回归 |
| 文档超 180 天未复核 | 提醒文档负责人 |
| 单租户 Token 消耗周环比 > 50% | 告警 + 排查异常调用 |
| 拒答率 > 30% | 告警（说明知识覆盖不足） |
| 拒答率 < 3% | 告警（警惕幻觉，需抽检） |

### 6.1 外部依赖

| 依赖 | 用途 | 风险 | 应对 |

### 6.2 关键约束

| 约束 | 说明 |
|---|---|
| **Embedding 锁定** | 换模型需全量重嵌，必须提供迁移工具链与双写灰度 |

## 7. 商业模式与计费设计

### 7.1 商业模式选项

| 模式 | 适用客户 | 收入构成 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 私有化买断** | 中大型企业、政企 | 授权费 + 实施费 + 年维保（授权费的 15–20%） | 客单价高、客户数据安全 | 交付重、难规模化 |
| **B. 订阅制（SaaS）** | 中小企业 | 按账号/坐席/月 + 用量 | 收入可预测 | 需多租户与运维能力 |
| **C. 按用量计费** | 有开发能力的企业 | Token + 存储 + 调用次数 | 弹性、公平 | 收入波动大 |
| **D. 混合模式（推荐）** | 全部 | 基础订阅（含额度）+ 超量按量 | 兼顾稳定性与增长 | 计费系统复杂 |

**推荐路径**：**先 A（私有化）→ 后 A+D（私有化 + 用量增值）→ 再 B（SaaS）**

理由：现有平台是私有化部署形态（Docker 离线镜像），直接做 SaaS 需重做多租户与运维体系。

### 7.2 定价参数设计（私有化）

| 计费项 | 计量单位 | 说明 |
|---|---|---|
| 平台授权 | 套/年 | 按知识库数量或用户数分档 |
| 用户席位 | 账号数 | 管理员 / 普通用户分档定价 |
| 文档量 | 文档数或存储 GB | 超量阶梯计价 |
| 向量规模 | 向量数（万） | 分档（100万 / 1000万 / 1亿） |
| 模型调用 | Token | 若使用我方模型服务 |
| 增值模块 | 模块/年 | GraphRAG、多模态、评测服务等 |
| 实施服务 | 人天 | 部署、数据迁移、定制开发 |
| 维保服务 | 年费 | 版本升级 + 技术支持（SLA 分级） |

### 7.3 成本结构（私有化场景）

| 成本项 | 说明 | 主要优化手段 |
|---|---|---|
| 模型调用 | LLM/Embedding/Rerank | 缓存、分层路由、批量 |
| 算力 | 向量库/模型推理服务器 | 按需扩缩、共享部署 |
| 人力 | 交付实施 + 支持 | 标准化交付包、自动化部署 |
| 研发 | 持续迭代 | — |

### 7.4 定价分档建议（示意）

| 版本 | 目标客户 | 包含能力 | 定价策略 |
|---|---|---|---|
| **基础版** | 部门级试点 | MVP 全部 + 单知识库 | 低门槛起步价 |
| **专业版** | 企业级 | + 多知识库 + 权限体系 + 评测 + 运营看板 | 按用户数分档 |
| **旗舰版** | 大型集团 | + GraphRAG + 多模态 + 私有化模型 + SLA | 定制报价 |
| **增值包** | 按需 | 渠道集成 / 定制插件 / 专属实施 | 单独计价 |
